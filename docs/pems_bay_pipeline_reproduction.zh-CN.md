# PEMS-BAY从零训练入口

该入口复现已分析的v1数据和实验设计，用于验证工程可用性，不能作为新的独立统计确认。每次运行在自己的目录重新产生数据绑定、预测权重、风险权重、校准设置、评测与审核；原冻结实验不覆盖。输入文件可放在其他位置，输出由`--workspace`统一管理，底层既有脚本在该目录的副本中使用相同相对路径。

本机验证已完成：独立工作目录`runs/pems-bay-reproduction-001`从零执行全部18阶段，数值差异0项，独立事件审核与完成后只读核对通过；各阶段执行合计1317.07秒。三个预测模型分别实测2375次优化更新，两个风险目标各三个MLP实测1350次更新。主检验仍未通过。读取审核首次受Windows沙箱临时目录权限阻止，保留失败日志，恢复后通过；共19次阶段尝试，18阶段最终完成。不是对安装全新环境或其他平台的验证。

## 安装与输入

本机验证环境为Windows、Python3.12、CPU PyTorch2.8.0，其他依赖见`requirements-pilot.txt`。在项目根目录安装：

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements-pilot.txt --extra-index-url https://download.pytorch.org/whl/cpu
```

自行获取DCRNN作者公开目录中的PEMS-BAY HDF5，文件大小须为135930936字节，SHA-256须为`65d69fb0a2323dba9867179eb7af47c8b814186bc459ff0a4937d21614153c8f`。入口在复制前和复制后均核对字节，拒绝其他文件，不猜测HDF5布局或自动换数据。本轮使用原已获取文件，没有重新下载。数据来源见`pipeline_seed/data/pems-bay-provenance.json`，不把镜像SHA称作者发布的官方校验值。

发布候选包已含`pipeline_seed/`，使用者无需自己构造。该只读种子包含原源码、固定设计、来源记录及原设计核验所需的METR-LA探索证据；另含原PEMS-BAY数值作为最后一步复核参考。它没有PEMS-BAY权重、预测/特征缓存或拟合阶段输出。参考数值不参与训练、选轮、阈值选择或预算构造，只在完整运行结束后比较。

原项目内如需首次构造种子，先运行`prepare_pems_bay_pipeline.py`；此脚本依赖原已冻结结果，不是终端使用者的下载或训练步骤。它也递归包含本地Python导入依赖并另存SHA，覆盖原执行冻结未列出的导入辅助文件。

## 一条命令运行全部阶段

在项目根目录执行，`--data`可用绝对路径；`--workspace`必须是该项目`runs/`内的新子目录：

```powershell
& .\.venv\Scripts\python.exe run_pems_bay_pipeline.py --workspace runs/pems-bay-reproduction-001 --data data/raw/pems-bay.h5
```

无需手动按顺序调用18个入口。流程为设计核对、绑定、读取审核/汇总、预测训练/审核/汇总、风险训练/审核/汇总、校准/审核/汇总、评测执行冻结、预审、固定设置评测、评测审核与汇总。最后另核对新运行产物和原记录数值。没有减少训练预算，也没有只跑几个样本的替代流程。

首次运行含三个预测器各25轮以及六个风险MLP各1350次更新，CPU上需要等待；耗时取决于机器。终端显示当前阶段，具体训练进度与错误写入`runs/<名称>/pipeline_records/logs/`。原预测训练本机耗时约15分钟，但这不是任意机器的时间保证。

开始时另存`portable_execution_manifest.json`，记录所有种子文件、入口、环境和原始数据SHA，明确数据已分析。每阶段前后核对种子和输入；子进程失败就停止，不继续后续校准/评测，也不降低统计门槛。运行锁防止同时写入同一目录。

## 停止后恢复与只读核对

同一来源、源码和目录下恢复：

```powershell
& .\.venv\Scripts\python.exe run_pems_bay_pipeline.py --workspace runs/pems-bay-reproduction-001 --resume
```

已完成阶段按记录跳过，失败或中断阶段重新调用其原入口。原入口仅复用有完整SHA日志的已完成权重/缓存；孤立的不完整文件会拒绝覆盖，此时保留目录并用新名称运行。`--resume`不等于删除失败痕迹。若仍有运行锁，先核对记录的PID和进程状态；入口不会自动抢锁或停止其他进程。

完成后只读核对：

```powershell
& .\.venv\Scripts\python.exe run_pems_bay_pipeline.py --workspace runs/pems-bay-reproduction-001 --verify-only
```

该命令核对种子、数据字节、冻结依赖、全部训练结果产物及数值比较，不重新训练、解码速度或计算新独立事件。跨硬件/库版本如出现数值差异会完整保存，不靠放宽容差、再选参数或改原记录来“复现成功”。

## 两个事先声明的兼容处理

空可用性组的风险评分在初次训练完成前使用零行适配：空输入返回空float32向量，非空输入调用原评分函数。训练样本、网络、损失、种子、更新次数和权重选择不变。训练后建立旧下游审核所需的兼容记录，保存11份权重SHA。

评测审核使用既有完成脚本的浮点列表比较：原标量abs1e−10/rel1e−12容差递归用于列表浮点值，整数计数和结构仍严格核对。该处理为原研究已知的约1e−14累计差修复，本次运行开始前已声明；不等待看结果再决定处理方式。复制的旧阶段报告或记录中“首次解封/事后修复”的措辞有原局部流程含义，须与本页和新运行总报告一起阅读，不能让本次已分析数据重新获得未见数据身份。
