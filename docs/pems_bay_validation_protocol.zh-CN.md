# PEMS-BAY未分析数据验证协议 v1

日期：2026-10-10。状态：方案已保存，尚未下载/绑定本项目的PEMS-BAY文件，尚未训练、校准或评测。配套机器配置为`configs/pems_bay_validation_v1.json`。文件哈希冻结是本地可追溯记录，不是外部机构预注册，也不证明算法原创。

## 目的与数据选择

终止METR-LA上的反复调参，检验当前流程在另一个此前未分析的网络上是否仍有同样的长提前量与服务取舍。候选方法固定为5分钟抽样的起点MLP，不根据新数据结果挑模型。

选PEMS-BAY，因为[DCRNN作者仓库](https://github.com/liyaguang/DCRNN#data-preparation)提供该数据的HDF5下载入口；[原论文](https://arxiv.org/html/1707.01926)说明其为湾区325个传感器的5分钟交通数据。实际文件的起止日期、列标识、时间连续性、速度单位与内容SHA-256必须在绑定时核验，不凭网页描述硬编码日期。当前只核验来源说明，尚未验证下载可用性、具体文件内容或再分发许可。

保留24站以控制CPU成本，绝不宣称覆盖完整325站网络。将文件列ID按`str(id).strip()`规范化；空值或重复规范ID直接停止。对每个ID计算UTF-8字符串`traffic-alert-pems-bay-24-v1|ID`的SHA-256，取哈希字典序最小24站（并列按ID），特征排列再按ID字典序。只看ID，不按拥堵次数、评测效果或未来缺测率选站。

选后检查最前42天每站自然有效率是否≥95%；有效指有限且严格大于0。失败就记录方案不可行，不能替换站点。新数据不能套用METR-LA权重：节点嵌入和地点特征依赖网络，需按同一结构重新训练。这检验跨网络流程复现，不是零样本迁移。

## 时间分区与访问边界

D0为实际首时间戳所在日的0点，采用文件自身时间轴，不擅自变换时区。半开日区间如下；数据不足126个日历日即报告不可行，不压缩测试段。

| 分区 | 相对D0的日区间 | 用途 |
| --- | --- | --- |
| 预测器训练 | [0,42) | 速度标准化、相关图、预测器权重 |
| 预测器验证 | [42,49) | 只选预测器训练轮次 |
| 风险层训练 | [49,77) | 共同有效样本、风险特征标准化、风险权重 |
| 风险层验证 | [77,84) | 只选风险权重/线性正则化 |
| 告警校准 | [84,98) | 误报预算、共同阈值与确认次数 |
| 一次评测 | [98,实际文件末尾) | 只回放已保存的运行点 |

全部历史/监督窗口须位于所属分区且5分钟连续。训练预测器的历史12步、未来3步不得越界；风险监督需历史12步至t+4不越界。前42天的相关图、标准化不得使用后续数据。

下载后的完整文件字节校验允许读取字节计算哈希；时间戳、列ID元数据可以核验。训练/校准准备程序不得读取第98天后的速度值、标签、缺测覆盖或预测，不能先计算测试事件数量。完整模型与校准选择、实现源码、配置和元数据绑定的哈希保存后才允许解封评测速度值。

现有通用`read_data/load_data`部分会读取完整HDF5值数组，不能直接用来宣称实现了上述隔离。下一步需实现按分区读取与访问门，并在解封前审核；本轮只完成方案和冻结工具。

## 固定任务与七组方法

人工故障只隐藏输入，不改原始速度代理标签或目标分母。三情景为自然缺测、全天单站故障、全天三站相关组故障。单站按相对D0日期序号模24轮换；三站组以前12个已选ID为中心，加训练相关性最高两邻站，平局按ID，日期模12轮换。组可重叠；相关组不是已证明空间连续的道路故障。过去故障读数不在第二天补回。

所有方法共享三种子缺测图TCN预测。结构和训练预算按机器配置固定：过去60分钟预测未来15分钟、32通道、1/2/4膨胀的门控时间卷积、8维节点嵌入、25轮、Adam0.001、batch128、mask后的有效目标L1，验证MAE选轮次。图使用训练期正相关top4与自环，不是官方DCRNN道路距离图，也不是DCRNN复现。三种子42/43/44全部进入平均，不挑最好种子。

风险特征沿用`congestion_risk_pilot.features`，24站时为51维；只含过去可见读数、缺测状态、预测、当前日历与站ID，未来原始值不进入在线输入。

七组固定为：密集速度规则、全局一维逻辑校准、按自身历史可用性分组的一维校准、51维持续低速逻辑回归、51维持续低速MLP、51维起点逻辑回归、51维起点MLP。前四组和起点线性为简单对照，全部报告，不只报较弱参考。

Y(t)为t到t+2三步原始速度均≤30mph；E(s)=Y(s)且非Y(s−1)；Z(t)=E(t)或E(t+1)或E(t+2)。所有风险模型训练与验证共享t−1至t+4六个自然有效读数的样本集合，每5分钟取样；线性/MLP使用各自的Y或Z监督。与部分旧实验不同，简单校准也统一这个样本集合，使新实验内部的样本口径一致，不能声称原实验原样复制。六读数有效性只用于监督，不能给在线告警过滤输入。

两MLP均51→32→16→1、ReLU、无权重BCE、Adam0.001、weight_decay0.001，种子202/203/204，batch4096，均匀有放回1350次更新，在225/450/900/1350步按对应标签验证BCE选权重，平局较早。监督不同的BCE不跨模型排名。线性用既有LBFGS、alpha=.0001/.001/.01，验证BCE选正则化；选定梯度最大绝对值须≤1e−4，失败时记录并在解封前解决实现/收敛问题，不能把未收敛模型作为弱基线。

分组依自身过去12步可用数为0、1–11或12。若某组训练不足100行、训练仅一类别或验证为空，回退全局模型并记录。标准化仅用共同有效风险训练池，三情景等权建立相同时间点池。

## 校准与主比较

预算不沿用METR-LA数值。在新数据校准段，用30mph速度规则、确认1次的每情景误报/有效站日建立该情景经验预算；对所有方法约束相同。预算为0也不得临时放宽，仅允许1e−12数值比较误差。预算仅在校准约束，必须报告评测是否超出，不能视为线上保证。

各方法在三情景使用一个共同阈值/确认次数，分别扫描粗细网格：概率细.010–.900步长.005加关闭值1.0001；粗沿用17点；速度细15–60mph步长.5，粗步长2.5，均加关闭设置；确认1/2次。细网格包含粗网格；速度分数为负的三步集成最大速度，按声明列表索引裁平局。完整枚举，不能假设误报告警段数单调。

保持历史选择目标：每情景预算可行后，平均**全部预警**召回最大、最差情景全部预警最大、平均误报最小、确认次数更小、声明网格索引更小。并没有改成按≥10分钟选阈值；这也意味着校准目标与主要服务指标的差别仍在被检验。

主要服务指标固定为原计分下≥10分钟召回，即10/15分钟档位成功开启数/完整代理事件数。**两项主要比较提前固定为起点MLP细网格分别减全局校准细网格、分组校准细网格。**不再通过校准全部预警挑一个唯一简单参考，因为它可能不是长提前量强对照。速度规则及其余四方法仍完整展示。

次要诊断为起点MLP减持续低速MLP、起点MLP减起点线性，以及每方法细减粗。它们不替换失败的主比较，不按效果把次要发现升级成确认性贡献。

## 事件计分、区间与判据

沿用`congestion_alert_pilot.event_stats`及密度实验档位实现：Y的连续真段构成低速代理事件，只在自然三读数有效的连续区间评测；左侧不足2步或右端触及有效区间末端的事件删失。告警仅按连续告警段的新开启一对一匹配，保持状态不能反复算新通知；开启触边删失，无法判定单列，匹配已检测事件算重复而非新增成功。开启a在[s−2,e)匹配事件[s,e)，a≤s计预警，提前档位为5×(s−a+1)分钟。

这些提前分钟是采样/代理计分公式，不是经过独立事故记录验证的物理拥堵起点。风险监督六读数mask不得替换评测三读数mask或分母。

报告全部七方法×三情景的≥10分钟、全部预警、含迟报检测、误报/有效站日、5/10/15档位、提前量、迟报、漏检、重复、未知、删失与覆盖；报告模型训练/推理及阈值扫描成本。日期计数在相同日历日期跨模型和情景联合重采样2000次，种子8120，每次重新计算各情景率再取三情景等权平均。区间条件于冻结模型，不含重新训练不确定性，也不把不同故障情景当独立事件。

主要两项长提前量差各给97.5%区间（两比较Bonferroni式保守处理），并列描述性95%区间；bootstrap是有限样本近似，日期相关与极少事件会影响区间可靠性。其他指标及次要比较95%区间均为描述性，不宣称所有历史/辅助检验的整体错误率受控。

验收分三层：

1. **可执行**：文件单位/时间轴/站点质量、分区、信息边界、模型收敛、校准选择与审核均通过；校准及评测完整事件和有效曝光均非零。事件少或区间宽时照实报告，不能换站、改30mph、裁日期来增加“显著性”。
2. **主指标支持**：两项预定≥10分钟差的97.5%区间下界都>0。仅一项通过、均包含零或为负，均不满足这个双强基线判据，不用次要指标救主结论。
3. **整体服务结论**：主指标支持不自动等于整体改善。若检测下降、误报增加/超预算，应称取舍；区间包含零不证明等价或非劣。本方案没有现场认可的容忍界值，也没有“整体优于”验收授权，需完整业务权衡再决定表述。

即使不通过也保存全部结果和负结论，不继续在该评测尾段改阈值、重训、换目标后宣称同一次验证成功。需要修改时建立v2及明确原因，并将已解封数据标为探索；确认仍需新数据。
